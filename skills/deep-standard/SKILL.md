# Deep Standard：可执行的工程标准

## 这套系统解决什么

一句话：**约定除非有程序会拒绝违规，否则等于不存在。**

绝大多数项目的"工程规范"是一份没人读、没人查、逐月腐烂的文档。本系统的全部设计都指向一个目标——让规范变成**可执行、可审计、可被 agent 在无状态条件下复现**的东西。它假设代码的主要维护者是**会被随时终止、下次只能靠文件系统恢复上下文的 agent**：任何只存在于对话历史或人类记忆里的约定，视为不存在。

本系统管的是**任何一个改动凭什么有资格落地**（质量平面），不管项目处在哪个阶段、下一步做什么（流程平面）。它独立可用，也可以叠加在任何流程/状态机之上。

## 六条法则

六条法则是这套系统的全部内容。每条都自包含，可以单独采纳；采纳顺序见[采纳阶梯](#采纳阶梯)。

### 法则 1 · 常驻规则分层，一个事实一个家

每个 session 都必须进入上下文的规则，集中在**一个有字数上限的常驻文件**（通常是根 `AGENTS.md`）里：每条 1–3 行、自包含、**只链接不复述**其详细归属。其余全部内容散到各自的唯一归属层级（子目录常驻文件、架构地图、类型目录、决策记录、菜谱、包 README）。

一个事实只有一个家。别处出现同一条规则时，改成链接。**字数上限是强制机制而非建议**：由门禁校验，红了以后依次尝试搬迁 → 压缩 → 最后才抬阈值，且抬阈值必须在 PR 里给理由。

→ [references/standing-orders.md](references/standing-orders.md)

### 法则 2 · 门禁即代码，且门禁必须自证

每一条机械可查的约定，都要有一个**只拒绝一条不变量**、非零退出、带清晰错误信息的程序。它们由一个编排器统一分组暴露（本地精选组 / CI 全量组）。

两条关键子规则：

- **门禁自证**：每个非平凡门禁必须有测试，用**合成的非法输入**证明它真的会拒绝，并断言错误信息。"拿真仓库跑一遍通过了"不是自证——那只证明当前仓库合法，不证明门禁有能力拒绝。
- **生成物防漂移**：所有生成的文档、目录、代码，都由生成器加 `--check` 模式守护（内存生成 → 与已提交文件逐字节比 → 不一致即失败）。**手改生成物一律禁止。**

→ [references/gates-as-code.md](references/gates-as-code.md)

### 法则 3 · 决策记录的生命周期即路径

决策记录（RFC / ADR 的等价物）落在 `{生命周期}/{分类}/yyyy-mm-dd-主题.md`：**状态写在文件里，也写在路径里，两者互为校验**，由格式门禁强制。分类取自一个封闭集合，加分类要同时改集合与契约文档。

三条硬性要求：

- **每个非平凡改动必须在同一个 PR 内新增或更新至少一条记录。** 只有纯机械的局部编辑豁免。更新已拥有该决策的记录即满足，不要造重复件。
- **`## Alternatives considered`（备选方案）强制存在。** 记录一个决策却不记它击败了什么，等于邀请日后重新扯皮——这正是决策记录存在的意义。备选方案只能记录，不能编造。
- **归档即永久冻结。** 已实施且不再指导未来工作的记录移入归档树，此后不得编辑、翻译、重排、移动，也不得当作当前行为的依据；由内容哈希清单守护。

一条记录永远不会被"改成另一个决策"——用新记录取代它，两边互链。新增记录时必须做**取代检查**：搜索现有树里覆盖同一决策或机制的旧记录，分类为完全取代（归档旧件）或部分取代（保持活跃并互链）。

→ [references/decision-records.md](references/decision-records.md)

### 法则 4 · 最小充分证据

每个改动只跑**能够覆盖它所触及表面的最窄证据**，一次。

- **测试分层，每层唯一归属执行点。** 同一层测试在同一提交上不得在归属点之外重复运行——重复运行不产生新信息，只产生耗时。
- **证据匹配改动面**：行为改动 → 最窄的那个测试；模型/用户可见输出 → 快照；文档 → 文档门禁组；发布路径 → 构建 + 构建产物冒烟；外部供应商行为 → 真凭证 e2e。
- **本地 hook 故意很窄**（暂存区格式/lint/空白/元数据守卫 + 增量类型检查），**CI 独占全量覆盖与平台矩阵**。
- **禁止默认跑全套**，禁止为了提交或推送重复跑一个已经通过的检查。只在明确要求、诊断 CI、或改动本身不可约简地遍及全仓库时才本地全量预演。
- **覆盖率是独立门禁而非"跑测试"的副产品**：未覆盖的行往往是门禁正确指出的死代码，不是要现补的测试；行覆盖必要但永不充分。
- **快照哲学**：昂贵/不确定的边界录一次真实数据，之后无凭证确定性重放；CI 强制只读重放；**修 fixture，不要修 normalizer**。

→ [references/evidence.md](references/evidence.md)

### 法则 5 · 散文只写契约，不写转录

注释与文档写**契约与非显然的定位信息**：行为、时序、模态、异常、后果、所有权、安全使用条件。删掉**推理转录**：实现过程叙述、显然分支的证明、测试走查、评审历史、被否决的局部方案、代码复述。

只写**当前态**。避免"以前/现在/不再/曾经"，避免 PR 号、commit、栈位置出现在长期散文里——直接命名活着的机制。变更故事属于 commit、PR、决策记录、事故复盘。

配一份 **slop 清单**（重复的家、叙述式历史、实现状态标注、手抄目录、段落墙、强调通胀、已实施记录里的规划语气……）当审计脚本用。长度本身从不是缺陷。

→ [references/prose.md](references/prose.md)

### 法则 6 · 落地纪律

- **一个 PR 一种性质**（feature / bug-fix / doc / testing / cleanup），加对应标签；独立的改动拆开。
- **在引入问题的那个 PR 上修，而不是往下游传播修补。**
- 依赖链用平台官方的栈机制，不要手工 merge + 改 base 复刻栈语义。
- 历史重写只用 `--force-with-lease`，远端有移动就中止，永不裸 `--force`。
- **多写者仓库显式协调**：并行 agent/协作者修改同一仓库时——同一文件同一时间只允许一个写者；存在未暂存改动时禁用 `git add -A`（显式路径 add，只暂存本次改动）；提交前检查未暂存文件，确认不吞入他人在途修改。详见 [references/landing.md](references/landing.md)。
- 未被明确要求时不推送、不合并、不发布。

→ [references/landing.md](references/landing.md)

## 两条元法则

**元法则 A · 现实优于教条。** 测试描述行为，不描述正确性——行为过时就连同它的测试一起改，并在 PR 里说明为什么。决策记录同样不是圣经：它记录当时的判断，不是不可推翻的真理。任何"因为测试/文档这么写所以必须这样"的论证都必须先证明该断言仍然对应真实需求。

**元法则 B · 显式声明阶段取舍档案，连同它的失效条件一起。** 项目在不同阶段的取舍不同（例：发布前无外部消费者时，"基础正确性优于兼容性负担"是对的；有了消费者就完全相反）。把当前阶段的取舍写成常驻文件顶部的一节，并**在同一节里写明何时删除它**（"首个正式版本发布时删除本节"）。没有失效条件的取舍声明会变成永久的技术债借口。**失效条件要配检查点**：写明由谁在哪个环节检查它是否已触发、判断产出什么（例：发布/分发动作前重评阶段取舍与档位，结论写入决策记录）——没有检查点的失效条件等于没写。

## 采纳阶梯

这套体系的收益随 **仓库寿命 × agent 参与度 × 契约面数量** 增长。给一个一次性脚本套全套就是过度工程。按档采纳，**不要跳档**：

| 档 | 适用 | 装什么 |
|----|------|--------|
| **L1** | 任何会活过一个月、有 agent 参与的项目 | 法则 1 的常驻文件（先不设字数上限）、法则 3 的决策记录（生命周期目录 + 强制备选方案段）、法则 6 的 PR 纪律、两条元法则；门禁只装一个：文档相对链接可达性 |
| **L2** | 有 CI、有多人/多 agent 协作、有外部消费者 | 加法则 2 的门禁契约与门禁自证、生成物 `--check` 防漂移、法则 4 的测试分层与唯一归属、窄 hook + CI 全量分工、法则 5 的散文契约与 slop 清单 |
| **L3** | 长期维护的多包/多契约面仓库 | 加字数预算门禁、覆盖率独立门禁与豁免机制、快照录制/重放体系、文档与代码的漂移门禁（文档里粘贴的类型/接口与源码一致性）、平台矩阵 |

档位判定与"装进现有项目"的完整流程（扫描 → 分层计划 → 逐项授权 → 执行）见 [references/adoption.md](references/adoption.md)。

## 反模式（见到就停）

- **写了规范但没有程序会拒绝违规。** 这是本系统要消灭的第一号问题。机械可查的约定必须有门禁；不可机械查的约定必须写明由谁在哪个环节判断，以及判断要产出什么依据。
- **门禁只在真仓库上跑通就算完成。** 未经自证的门禁可能永远不会失败，比没有门禁更危险——它提供虚假的安全感。
- **同一条规则出现在三个文件里。** 一处修改另两处腐烂，agent 读到互相矛盾的版本。搜索一个特征短语，留一个家，其余改链接。
- **默认跑全套测试来"确保安全"。** 这既拖慢每个改动，又让人对信号麻木；它掩盖的是"不知道该跑什么"，正确的解法是把改动面与证据的映射写下来。
- **只有结论没有依据的自我审查。** agent 声称"已检查、没问题"而不给依据与证据路径，等于盖章。凡是标注"由 agent 判断"的检查项，都必须产出结论 + 依据 + 证据路径。
- **在已实施的决策记录里写规划语气。** "应该""待迁移""验收标准"属于提案期；已实施的记录只描述现实。
- **为了让门禁变绿而放宽门禁。** 抬字数上限、加豁免、跳过检查，都必须作为独立的、有理由的决定被记录；把它偷偷混在功能 PR 里是最典型的规范腐烂路径。安全相关的门禁与发布最小间隔一类的策略配置，永远不允许为了让 CI 通过而修改——升级给人类。
