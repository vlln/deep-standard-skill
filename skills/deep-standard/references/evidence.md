# 最小充分证据

## 原则

**每个改动只跑能够覆盖它所触及表面的最窄证据，一次。**

反过来说：没有"通用本地基线"这种东西（除了必过的窄 hook）。每个行为改动需要**那个会因它的回归而失败的最窄测试或专用检查**；只有 diff 真的触达的表面才追加更广的检查。

违反这条的两个方向都要禁止：跑得不够（改了行为却只跑类型检查）、跑得太多（默认全套）。后者危害同样严重——它拖慢每个改动、让人对信号麻木，并且掩盖了真正的问题："我不知道该跑什么"。正确解法是把改动面到证据的映射写下来。

## 测试分层，每层唯一归属

每一层测试只有**一个归属执行点**。同一层测试在同一提交上不得在归属点之外重复运行——重复运行不产生新信息，只产生耗时。

| 层 | 回答什么问题 | 归属执行点 |
|----|-------------|-----------|
| 单元 / 模块测试 | 这个模块的契约成立吗？ | 本地按改动面精选；CI 覆盖率门禁内 |
| 覆盖率门禁 | 每一行都被执行过吗？ | CI 专门 job（带插桩） |
| 快照 / 契约测试 | 组装起来的系统对外输出符合预期吗？ | CI 快照 job；本地按改动面跑单个场景 |
| 构建产物冒烟 | 发布出去的制品真的能跑吗？ | CI 产物 job（必须先构建） |
| 真凭证 / 真外部依赖 e2e | 面对真实的外部系统它还成立吗？ | 独立 workflow（受信任事件触发：主干推送、定时、受信 PR） |
| 平台矩阵 | 在支持的每个平台/运行时版本上都成立吗？ | CI 独立 job |
| 冒烟（发布后） | 部署/发布出去的东西活着吗？ | 发布流程，每个环境一次 |

失败修复后的重跑**从失败层开始**，不回溯已经通过的层。

## 证据匹配改动面

把这张表实例化到项目里，写进常驻文件（一行）+ 本文件的项目副本（详表）：

| 改动触达 | 跑什么 |
|---------|--------|
| 某模块/脚本的行为 | 拥有它的那个测试文件，或按测试名精确过滤 |
| 文档、决策记录、生成目录 | 文档门禁组（链接、格式、生成物新鲜度、预算） |
| 模型/用户/协议可见的输出 | 对应的快照场景（通过真实可运行的入口，不是 mock 组合） |
| 包清单、公开导出、构建配置 | 构建 + 相关清单卫生检查 + 拥有它的构建产物冒烟 |
| 与真实外部服务的交互 | 有凭证时跑对应的真 e2e |
| 依赖图 / 分层约束 | 依赖约束门禁 |
| 并发、生命周期、子进程、拆卸 | 该领域的专项测试 + 见项目的危险模式文档 |

**不确定跑什么，就先确定改动触达了哪些表面**——这个问题比"跑哪些测试"容易回答得多，而且答案可复用。

## hook / 本地 / CI 分工

**Git hook 故意很窄**，因为慢 hook 会被绕过，绕过一次就永远失效：

- `pre-commit`：只处理**暂存区**——格式化、lint（含自动修复）、空白错误、需要同步的元数据守卫、必要的再生成。
- `pre-push`：只跑增量的**类型检查/编译**一类快速全局信号。
- **hook 里不跑**：测试、快照、文档门禁、构建、全量卫生检查。

**本地**：按改动面精选证据，跑一次。

**CI 独占**：穷尽覆盖、平台矩阵、构建产物验证、全量快照。CI 分组的原则是把独立门禁并成宽 lane，需要构建产物的消费者在自己 lane 内等一次构建。

**凭证策略**：主 CI **无凭证也必须全绿**——需要凭证的测试自行跳过。同时必须有一个**预检**防止"因为缺凭证而全部跳过"被误读为通过。需要凭证的测试放独立 workflow，只在受信任事件上触发。

## 覆盖率

覆盖率是**独立门禁**，不是"跑测试"的副产品：门禁跑的是带插桩的那次运行，无插桩的运行证明不了阈值。

- 阈值定在**按文件**而非全仓库聚合：聚合阈值允许新代码零覆盖被旧代码稀释掉。
- **未覆盖的行往往是门禁正确指出的死代码，不是要现补的测试。** 先问"这行还需要存在吗"。
- **行覆盖必要但永不充分**：它证明行跑过了，不证明功能按发布形态正确工作。不要用覆盖率数字代替快照/e2e 层的判断。
- **豁免必须有成员契约**，不是随手加白名单。可接受的契约形如："某个套件被移出插桩运行的条件是——它在进程内执行到的每个被测量文件都已被其他套件完全覆盖，因此移除它不改变任何阈值结果。" 需要外部工具/环境才能跑的文件同理：测试自行跳过 + 该文件显式豁免，让缺该工具的机器保持绿色。

## 快照与 fixture

快照回答"组装起来的系统对外输出是否符合预期"，是唯一能守住**跨越多个模块的可见行为**的层。

- **每个非平凡的、模型可见 / 协议可见 / 用户可见的行为改动，必须在同一个 PR 内通过真实可运行的入口新增或更新一个快照场景。** 模块测试、e2e 断言、mock/测试专用组合、以及 PR 说明，**都不能替代**组装后的真实记录。
- **录一次真实数据，之后无凭证确定性重放**：昂贵/不确定的边界（外部 API、网络、时钟、随机源）录制成 fixture，之后所有运行从 fixture 重放。
- **CI 强制只读重放**，永不写入期望输出。录制与刷新只在本地进行，每一处 diff 都要被人评审。
- **只 mock 昂贵或不确定的那个边界，下游全部保持真实。** 手搓的替身只能证明桥能传字节，不能证明发布出去的东西行为正确。
- **e2e 断言必须从外部验证世界**（重新执行命令、重新读文件、查询真实状态），而不是读被测系统自己的输出。对自述输出做关键词探测，会让一个"作弊"的实现轻松通过。
- **fixture 必须在所有支持的平台上可重放；修 fixture，不要修 normalizer。** 放宽 normalizer 是把跨平台缺陷藏起来的最快方式。平台中立行为的测试要用宿主的路径/URL API 构造路径，然后按契约断言原生绝对路径或稳定的相对路径。
- 平台专属的排除项，必须在旁边留一条跨平台断言覆盖它所支撑的产品行为。

## 确定性纪律

不确定的测试比没有测试更糟：它训练所有人忽略红灯。

- **等完成信号，不等时间。** 禁止用 sleep/延时作为同步手段。
- **禁止对瞬态状态做单次采样断言**（流式中间态、动画中、临时 DOM/日志片段）——每一跳都可能合并或重排，采样即竞态。断言终态或断言完整序列。
- **禁止把轮询文件/日志当作完成或持久化屏障**——用系统自己暴露的空闲/完成信号。
- 协议形状、组合爆炸类的代码（编解码器、状态机、事件日志）优先用基于属性的测试。

## 断言的语义纪律

- **测试描述行为，不描述正确性。** 行为过时就连同它的测试一起改，并在 PR 里说明为什么。测试不是黄金真理。
- 断言要盯**权威来源**（真实的事件流、可变状态、外部可观测结果），而不是"某个方法/服务存在"这类静态存在性——后者几乎不会失败，也几乎不说明任何事。
- 测试与它所验证的代码同层归属；测试基建、fixture、脚手架的文档属于最低的拥有层。
