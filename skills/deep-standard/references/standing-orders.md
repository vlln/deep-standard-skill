# 常驻规则分层

## 问题

agent 的上下文是稀缺资源，而项目的约定是无限的。把所有约定塞进常驻文件，agent 会淹没在细节里并开始忽略它；只写高层原则，agent 会在具体决策点上自由发挥。解法是**分层**：常驻层只放"每个 session 都必须知道"的东西，每条都指向它的详细归属。

## 常驻层的形态

常驻文件（根 `AGENTS.md` 或等价物）是**立正命令表**，不是手册：

- 每条规则 **1–3 行**，自包含（读这一条就能不犯错），**链接它的家**（读那个家才知道细节与理由）。
- 内容限于：项目定位一句话、目录布局、常用命令、必须常驻的约定、编辑本文件的规则。
- **不放**：故事、完整示例、情境化流程、任何从被链接的家里复述来的内容。
- 有子目录需要自己的立正命令（如 `packages/`、`docs/`、决策记录树），给该子目录一个自己的常驻文件，只放**该子树特有**的命令，不重复根文件已经承载的全仓库规则。

规则的写法决定它会不会被遵守。对比：

```
差：注意保持代码风格一致，遵循现有约定。
好：跨包引用用包名，包内相对引用带扩展名；理由与例外见 <链接>。

差：重要改动要写文档。
好：每个非平凡改动必须在同一 PR 内新增或更新至少一条决策记录；豁免范围见 <链接>。

差：尽量不要硬编码配置。
好：随部署环境变化的选择必须是经校验的配置字段，不是 DEFAULT_* 常量；协议常量、外部规范、安全不变量保持固定。
```

规律：**可判定**（能对着 diff 回答是否违规）、**有边界**（说明例外或指向例外）、**命名活着的机制**（不说"应该"，说"是"）。

## 一个事实一个家

给每类事实指定唯一归属层，别处只链接。层级划分按**这个事实的工作是什么**，不按文档类型。一份可直接改用的分层表在 [assets/templates/docs-AGENTS.md](../assets/templates/docs-AGENTS.md)，典型层级：

| 层 | 它的工作 | 不属于它 |
|----|---------|---------|
| 根常驻文件 | 立正命令：每个 session 都需要的规则，每条 1–3 行并链接其家 | 故事、示例、情境流程、任何复述 |
| 子树常驻文件 | 该子树特有的命令 | 根文件已承载的全仓库规则 |
| 架构地图 | 系统地图：模块、主流程、扩展点——改动核心代码前必读 | 类型形状、单模块细节、决策理由、实现状态标注 |
| 类型/接口目录 | 骨干词汇的字面形状与语义 | 行为叙述 |
| 决策记录 | 决策与理由，受自己的生命周期契约管辖 | 迁移计划、验收清单（一旦实施完成） |
| 事故复盘 | 事故故事——**唯一**允许战斗故事叙事的层 | — |
| 危险模式文档 | 按危险领域分类的"缺陷类"规则：生命周期、并发、子进程、拆卸等。每条来自真实发生过或差点发生的缺陷，写成防止复发的规则；进入这些领域前必读 | 单次事故的经过（→ 事故复盘）、通用编码风格 |
| 菜谱 | "怎么新增一个 X" 的编号步骤 + 结尾验证命令 | 设计理由（链接到决策记录） |
| 模块/包 README | 该模块的配置、语义、已知限制、扩展点 | 复述 API 文档注释、别的模块的事 |
| 贡献者指南 | 环境搭建、日常流程、CI 形态（概要级） | 运行时理由、会漂移的门禁清单 |
| 生成目录 | 从源码再生成的穷尽枚举，由新鲜度门禁守护 | 任何手改 |
| 用户文档 | 面向产品用户的指南 | 生成的参考表、贡献者流程、决策史 |

判定归属的顺序：**先定位这个事实在树上的位置**（它的主题被谁拥有）→ 定它允许的细节深度（描述自己的主题可以详尽；描述直接子节点只写用途、职责、高层行为；更低层细节链接到拥有它的后代）→ 定它是教程还是参考。

**文档类型不会扩大它的范围。** 一份参考可以对自己的主题穷尽，不能顺手把子节点的细节也写完。测试机制、fixture、脚手架属于最低的拥有层，上层只链接。

## 可移植的约定候选清单

常驻层放什么由项目决定，但下面这些约定跨语言、跨领域都成立，且实践中反复证明值得占据常驻层的位置。装进项目时逐条评估，不适用的删掉，**不要照单全收**：

- **随部署环境变化的选择必须是经校验的配置字段**，不是常量或测试钩子；协议常量、外部规范、安全不变量保持固定。
- **配置错误要响亮地失败**：能自包含判定的在加载时失败，否则在最早可判定处失败；绝不静默跳过缺失的引用目标。
- **默认值的解析是边界上一个显式的步骤**，不是执行路径深处一个隐藏的"取不到就用这个"。请求进来先解析成完整的规格，再执行。
- **空的异常捕获必须写明它吞掉了什么、以及为什么不会有别的东西到达这里**，`try` 只包一条语句。
- **优先用维护良好的依赖，而不是自己手搓**——判据是它**真的删掉了自己拥有的代码和测试**、依赖本身健康、在边界上契合，且不是一条已经稳定的自有缝。反过来，为了省一个小函数引入一棵依赖树是净损失。
- **并列的值优先保持对称**；没有解释的不对称通常意味着漏掉了一次抽象。
- **运行时不变量断言的是自己拥有的动态关系**（权威事件流、可变状态随时间的演化），不是"某个服务/方法存在"这类静态存在性检查——后者几乎不会失败，也几乎不说明任何事。确实没有可断言关系时，写明"无运行时不变量"及原因，而不是塞一个假检查。
- **封闭的枚举/联合要穷尽处理**（编译期可查的语言用穷尽性检查，否则显式 default 抛错）；开放可扩展的则必须有一个被文档化的默认分支。
- **跨边界的不透明标识符用具名类型包裹**，不用裸字符串——各语言的对应物：newtype、branded type、value object、NewType。
- **在类型/契约已经保证的同进程边界上信任它**，不要重复加运行时校验；校验只放在真正的信任边界：解析与配置、外部输入、持久化与文件、进程与线程边界、网络与协议。

各语言/框架特有的约定（构建平面划分、模块系统细节、框架生命周期语义）属于项目自己的常驻层，不属于本清单。

## 教程与参考分离

每份文档明确是**教程**还是**参考**：

- 教程沿一条有序路径通向一个结果，每步只引入这一步需要的东西。写之前先私下给读者的起点知识与每个概念分级（初/中/高），先建立前提再引入依赖它的概念，难度渐进，不必要的高级材料挪到后面的教程或参考里。
- 参考定义一个查询范围，描述当前行为，不依赖任何教学顺序。

两者内容都可观时**必须分开**；其中一侧很小时用清晰的结构边界（章节）隔开。混在一起的后果是两类读者都读不下去：想学的人被穷尽枚举打断，想查的人要读完故事才找到那一行。

## 字数预算：把"一个事实一个家"变成强制

分层规则如果没有强制机制，会以完全可预测的方式腐烂：每个人都往常驻文件里加"就一句话"，半年后它变成 6000 字没人读的手册。

机制：给每份**长期文档**设字数上限，写进一份 manifest（示例见 [assets/templates/doc-budgets.manifest.json](../assets/templates/doc-budgets.manifest.json)），由门禁校验超限**与文件缺失**两个方向。

门禁变红时，按顺序尝试：

1. **搬迁** 属于别层的内容，必要时留一行链接。
2. **压缩** 确实属于本层但可以更短的内容。
3. **抬阈值**——仅当这些字真的需要这个空间，且必须在 PR 里为 manifest 的改动给出理由。

三条纪律：

- **上限是护栏，不是缩减目标。** 在目标以下时保留至少 5% 余量；超过目标时**冻结上限**，直到搬迁或压缩把文档压回目标以下。
- **过低的上限是预算 bug**，不是文档的错。内容确实需要空间时就抬阈值——因为上限太低而删掉真实契约是最坏的结果。
- 只在契约确实还有余地时才下调上限。

L3 才装这个门禁。L1/L2 靠评审执行同样的判断：一条规则要进常驻文件，先问"它能不能改成一行链接"。

## 编辑常驻文件

- 常驻文件被别的路径（如 `CLAUDE.md`）软链或镜像时，**编辑真实文件**，不要编辑镜像。
- 每条规则保持自包含，同时链接高层文档。
- 能在保住清晰度的前提下压缩就压缩；确实需要更多空间时才抬预算上限。
- 常驻文件的改动同样受法则 3 管辖：改的是规则，就要有决策记录说明为什么。
