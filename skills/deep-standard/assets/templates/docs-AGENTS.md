# docs/AGENTS.md — 文档标准

本文件定义文档结构、分层归属、写作规则<!-- L3：、以及字数预算上限 -->。它是文档规范的唯一归属：根 `AGENTS.md` 只留一行链接过来。

## 分层：一个事实一个家

每个事实只有一个家——那个"以承载它为职责"的层。别处出现同一事实时，改成链接。

| 层 | 它的工作 | 不属于它 |
|----|---------|---------|
| 根 `AGENTS.md` | 立正命令：每个 session 都需要的规则，每条 1–3 行并链接其家 | 故事、示例、情境流程、任何复述 |
| 子目录 `AGENTS.md` | 该子树特有的命令 | 根文件已承载的全仓库规则 |
| `docs/architecture.md` | 系统地图：模块、主流程、扩展点——改动核心代码前必读 | 类型形状、单模块细节、决策理由、实现状态标注 |
| `docs/<类型目录>/` | 骨干词汇的字面形状与语义 | 行为叙述 |
| `decisions/` | 决策与理由，受其[自身契约](../decisions/README.md)管辖 | 迁移计划、验收清单（一旦实施完成） |
| `docs/postmortem/` | 事故故事——**唯一**允许战斗故事叙事的层 | — |
| `docs/defensive-patterns.md` | 按危险领域分类的缺陷类规则（生命周期、并发、子进程、拆卸）；进入这些领域前必读 | 单次事故的经过（→ postmortem）、通用编码风格 |
| `docs/cookbook/` | "怎么新增一个 X" 的编号步骤 + 结尾验证命令 | 设计理由（链接到决策记录） |
| 模块/包 README | 该模块的配置、语义、已知限制、扩展点 | 复述 API 文档注释、别的模块的事 |
| `docs/development.md` | 贡献者上手：环境、日常流程、CI 形态（概要级） | 运行时理由、会漂移的门禁清单 |
| 生成目录 | 从源码再生成的穷尽枚举，由新鲜度门禁守护 | 任何手改 |
| `docs/user/` | 面向产品用户的指南 | 生成的参考表、贡献者流程、决策史 |

**文档类型不会扩大它的范围。** 一份参考可以对自己的主题穷尽，但描述直接子节点只写用途、职责、高层行为，更低层细节链接到拥有它的后代。测试机制、fixture、脚手架属于最低的拥有层。

## 教程与参考

每份文档明确是教程还是参考。教程沿一条有序路径通向一个结果，先建立前提再引入依赖它的概念，难度渐进；参考定义一个查询范围，描述当前行为，不依赖教学顺序。两者内容都可观时必须分开，其中一侧很小时用清晰的章节边界隔开。

写作顺序：定位它在树上的位置 → 定它允许的细节深度 → 选教程或参考 → （教程）按前提与难度排序概念 → 把后代拥有的细节搬走 → 把低层解释换成指向其归属的链接。

## 写作规则

- **只写当前态。** 避免"以前/现在/不再/曾经"，长期散文里不出现 PR、commit、分支位置——直接命名活着的机制。变更故事进 commit、PR、决策记录、事故复盘。
- **每个非平凡改动在同一 PR 内新增或更新至少一条决策记录。**
- **注释与文档写完整契约，不写推理转录。** 保留行为、时序、模态、异常、后果、所有权、安全使用条件；删除实现叙述、测试走查、评审史、代码复述。理由只写在拥有它的那一处。
- **跨引用用可机械校验的相对路径链接**，不用裸文件名或编号。链接门禁通常只校验文件存在、不校验锚点——锚点自己核。
- 读者是专业程序员：简洁直白优于比喻；不要滥用某几个抽象名词。
- <排版规则，例如：一段一物理行，靠编辑器软换行；代码块/表格/列表保持自身格式；代码注释遵守 linter 列宽>
- <双语项目：任一侧改动都同时义务化另一侧，并在同一改动内完成>

## slop 清单

审计任何文档都过一遍：同一条规则有两个以上的家 / 叙述式历史与战斗故事 / 实现状态标注 / 手抄的目录与清单 / 推理转录 / 理由抄在并列成员旁边 / 段落墙 / 强调通胀 / 已实施记录里的规划语气 / 空壳章节。

**长度本身从不是缺陷。**
